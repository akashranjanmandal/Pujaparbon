# Deploying Pujo Parbon Seller OS on Render (free)

One free Render web service runs both the website and the API in a single Node process
(`npm run start:render` → `apps/api/src/combined.ts`). The database stays on Turso.

## 1. One-time setup (about 10 minutes)

1. Sign in at <https://dashboard.render.com> with the GitHub account that owns
   `akashranjanmandal/Pujaparbon` (or give Render access to that repo).
2. **New → Blueprint** → choose the `Pujaparbon` repo → Render reads `render.yaml`.
3. Render asks for the one secret it cannot generate:
   - `TURSO_AUTH_TOKEN` → paste the **database** token (the `TURSO_AUTH_TOKEN=` value in `apps/api/.env`
     on the developer laptop, or create one with `turso db tokens create pujoparbon`).
4. Press **Apply**. The first build takes 5–8 minutes. When it is live you get a URL like
   `https://pujaparbon.onrender.com`.
5. Open `https://<your-url>/api/v1/health` — it should show `{"ok":true,"db":"turso"}`.

That's it. Every push to `main` redeploys automatically.

## 2. What the blueprint sets

| Setting | Value | Why |
| --- | --- | --- |
| Plan | Free | ₹0 |
| Region | Singapore | Closest Render region to India; Turso DB is in Mumbai |
| Build | `npm ci --include=dev && npm run build --workspace apps/web` | Builds the Next.js site |
| Start | `npm run start:render` | Runs DB migrations, then serves web + API on one port |
| Health check | `/api/v1/health` | Render restarts the service if this fails |
| `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET` | generated by Render | Login security; never stored in git |
| `NEXT_PUBLIC_DEMO_MODE` | `true` | Shows the "simulate being at the warehouse" option so the client can try check-in remotely. Set `false` for real daily use, then redeploy. |

## 3. Things to know about the free plan

- **Sleeps after 15 minutes without visitors.** The next visit takes about a minute to wake up.
  Fine for demos. For daily warehouse use, switch the service to a paid instance in Render.
- **Nothing is lost on restart.** Attendance selfies, uploaded platform reports and invoices are stored in the Turso database, not on the server's disk, so Render's free plan restarts do not delete them.
- **750 free instance hours per month** per Render workspace — enough for one service.

## 4. Custom domain (optional)

Render → service → **Settings → Custom Domains** → add e.g. `app.pujaparbon.in`, then add the
CNAME record Render shows at your domain registrar. HTTPS is issued automatically.

## 5. Loading or resetting demo data

The live site uses the Turso database directly. From a developer laptop with `apps/api/.env` filled in:

```bash
npm run db:setup      # migrations + demo data (wipes and rebuilds the demo tenant)
```

## 6. Troubleshooting

| Symptom | Fix |
| --- | --- |
| Build fails at `npm ci` | Make sure `package-lock.json` is committed. |
| `/api/v1/health` shows `"db":"local"` | `TURSO_AUTH_TOKEN` is empty — set it in Render → Environment and redeploy. |
| Login works then logs out at once | The site must be opened over `https://` (Render URL or custom domain). |
| Staff check-in says location/camera blocked | The site must be on `https://`; the staff member must allow Location and Camera for it in the browser. |
